# Codex 0.145.0 activity acceptance matrix

This matrix is authored acceptance evidence for the pinned Codex app-server protocol version **0.145.0**. It describes what Portcode projects into the transcript/activity UI, what is retained only as a bounded diagnostic, and what is intentionally deferred. The implementation remains additive: normalized transcript events are unchanged, while safe activity and final-snapshot events add convergence data.

## Security invariant

Raw reasoning is never a display feature. Opaque reasoning required for provider continuation may remain in the private desktop persistence model, but the Codex activity sanitizer, public projection, frontend compatibility sanitizer, transcript snapshot mapper, DOM, accessibility tree, and copy source all fail closed before it can become visible or remotely replicated.

## FR-005 / RISK-010 native inspection invariant

Known credential-bearing keys are matched after ASCII case and punctuation normalization. The explicit set covers API keys; passwords and passphrases; authorization and proxy-authorization material; credential(s); secrets and client secrets; access, refresh, ID, auth, bearer, session, and generic tokens; private keys; cookies and set-cookie values; bearer material; and explicit auth/authentication fields. Their values are recursively replaced with non-sensitive markers before native persistence or CodexEvent emission and again at the frontend compatibility boundary for legacy rows. Safe correlation, status, summary, and benign unknown metadata remain visible. The public/remote path remains a bounded metadata-only DTO and may carry the allowlisted reason knownSecret, never the source field value.
